# HASHOUT_LOG, Go server, formnet

## 2026-11-22 · Port takeover order

8760 (API and web client) and 8761 (proxy) stay the preferred ports, whether they come from the defaults or from `FORMNET_ADDR` / `FORMNET_PROXY_ADDR`. At `serve` start both are bound first and only then read back, so there is no gap between picking a port and holding it; `proxy.Serve` takes the bound listener for this (`ListenAndServe` stays for the tests and wraps it).

When a bind fails, in this order:

1. Look for a leftover FormNET: `GET /healthz` on the taken API address and on the address the last run wrote to `endpoints.json`. Only an answer with `product: formnet` counts, and only when that FormNET holds a port this run wants (its API address, or the proxy address its health body names; an older body without `proxy_addr` counts for the default pair).
2. Ask it to stop with `POST /api/quit` and the last run's token, then retry both binds every 100 ms for up to 5 s. The old server closes its listeners at once on shutdown, so the ports come free well inside that.
3. If the quit is not accepted (an older build without the route, or a token that no longer matches), fall back to the pid in `endpoints.json`, but only when that pid is the process listening on the address right now and its program name starts with `formnet`. SIGTERM on Unix (the old run then shuts down cleanly), terminate on Windows. A process that did not identify as FormNET is never signalled.
4. Whatever is still taken: bind port 0 on the same loopback host, write one plain line to stderr naming the port and its holder (process name and pid from `machine.Listening` when the platform tells this user, "another program" otherwise, "another FormNET that would not stop" when step 2 and 3 failed), and put the same sentence into `/api/status` as `notices`. The status bar shows it in the hint slot. The desktop ready line, the Host guard and the proxy's refuse list all use the addresses actually bound.

Why move instead of fail: the desktop window starts FormNET as a sidecar and cannot ask the person to free a port; a FormNET on another port that says where it is beats no FormNET.

## 2026-11-22 · The quit route needs the token

`POST /api/quit` sits under `/api/`, so it needs the run's bearer token like every other route, and the write guard refuses it from a browser page on another origin. Without the token any program or any web page that can reach loopback could stop someone's recording. The new process reads `<data>/token` before it writes its own, so only someone who can read that file (the same user, mode 0600 or a user-only access list) can stop the old run. The handler answers 202 before it stops, so the caller knows the request was taken.

## 2026-11-22 · The endpoints file

`<data>/endpoints.json` is how other programs find FormNET after a move. Fields: `product`, `version`, `pid`, `addr`, `proxy_addr`, `ca_path`, `started` (UTC). Written atomically (a private temporary file renamed over the old one) once both listeners serve, readable by the user only, and removed on a clean exit. A stopping run removes it only while the file still names its own pid, so the run that replaced it keeps its file. It never holds the token or anything recorded. `formnet url` and `formnet open` read `addr` from it and fall back to the configured address when it is missing. `/healthz` now also says `proxy_addr` and `proxy_listening`, so a caller without the token can confirm the file and find the proxy.

## 2026-11-22 · Windows access lists through advapi32, not icacls

The root key, the token file and the endpoints file are created on Windows with a security descriptor that grants the current user full control and nothing else, with inheritance turned off (`D:P(A;;FA;;;<user SID>)`). `checkKeyMode` reads the key's access list and refuses it when an account other than the user, SYSTEM, the Administrators or the owner rights entry may read it, naming the accounts and giving the exact `icacls` line that fixes it (`/inheritance:r`, `/grant:r` for the user's SID, `/remove:g` for explicit entries).

Chosen over running `icacls.exe`: the descriptor is applied in the same `CreateFile` call that makes the file, so there is no moment when the key exists with the folder's inherited access; there is no child process (no window, no PATH or SystemRoot lookup, no timeout); and nothing depends on icacls output, which is localized and changes between Windows versions. The cost is a few `syscall` calls into advapi32 (`ConvertStringSecurityDescriptorToSecurityDescriptorW`, `GetNamedSecurityInfoW`, `ConvertSecurityDescriptorToStringSecurityDescriptorW`), still standard library only. Existing installs keep working: a key in the user profile inherits SYSTEM, Administrators and the user, which the check allows. The key stays a file only the user can read; it is not moved to a system password store.

## 2026-11-22 · Windows trust commands use double quotes

`certutil` lines printed for Windows wrap the path and the certificate name in double quotes: single quotes are not quotes in cmd.exe. A Windows path cannot hold a double quote. Unix lines keep POSIX single quoting.

`netstat` and `tasklist` run with `HideWindow` and `CREATE_NO_WINDOW`, so the desktop app no longer flashes a console every two seconds. The browser opener (`rundll32 url.dll,FileProtocolHandler`) is a GUI program, opens no console, and runs only from `formnet open` in a terminal, so it is left as it was.

## 2026-11-22 · netstat rows by column position

`netstat -ano` prints its TCP state in the system's language (`ABHÖREN`, `HERGESTELLT` in German). Rows are now read by position: protocol, local address, foreign address, then the state words, and the pid in the last column. Known English states map as before (`LISTENING` becomes `LISTEN`); an unknown word is `LISTEN` when the foreign address is `0.0.0.0:0`, `[::]:0` or `*:*`, and an established connection otherwise. UDP rows carry no state and stay `UDP`. Localized states that are neither (a localized `TIME_WAIT`) show as established, which keeps the row and its owner visible rather than dropping it.

## 2026-11-22 · A flow when a client refuses the opened connection

A CONNECT that formnet opens and whose client then does not finish the TLS handshake (a program that pins its certificates, or one that does not trust the root) is stored as a flow of kind `refused`: scheme `https`, method `CONNECT`, the host and port, the client and its process when the machine view knows them, `pending: false`, `tls.intercepted: true`, `tls.server_name` when the client sent one, and `error` of the form `the client refused FormNET's certificate: <reason>`. Start is when the handshake began. The reason is the alert the client sent (`unknown certificate authority`, `bad certificate`), or `it closed the connection during the handshake`, `the handshake timed out`, or, for a TLS 1.3 client whose alert arrives under keys the server cannot read yet (Go reports `bad record MAC`), `it ended the handshake after it received the certificate`. Measured with curl: TLS 1.2 gives the alert name, TLS 1.3 the last form.

A burst is collapsed: at most one refused flow per program (pid and name, or the client IP when the owner is unknown) and host per 2 seconds; repeats inside the window are dropped, because the Flow type has no count field to carry them. The map of last refusals is pruned of old entries once it holds 256 keys. A client that sends nothing never reaches the handshake (it is relayed as before), and with interception off nothing is opened, so neither records a refusal. Host summaries count a refused flow under its host and as an error, but do not mark the host `intercepted`, since nothing inside was seen. HAR exports leave refused flows out, like tunnels: they have no HTTP shape.

## 2026-11-22 · HAR without secrets by default

`GET /api/export/har` now writes the values of `Authorization`, `Proxy-Authorization`, `Cookie` and `Set-Cookie` (any case) as `[redacted]`; the `cookies` lists were already empty and stay so. No existing test asserted a captured secret, so none changed.

## 2026-11-22 · br and zstd bodies decoded for display

Captured bodies with `Content-Encoding: br` or `zstd` are decoded for display as gzip and deflate were, with `github.com/andybalholm/brotli` v1.3.0 (MIT) and `github.com/klauspost/compress/zstd` v1.20.5 (BSD-3-Clause; its linked `zstd/internal/xxhash` is MIT and `internal/snapref` BSD-3-Clause), both pure Go; rows in `NOTICES.md`. A list such as `br, gzip` is undone last applied first; `identity` is skipped. The proxy still relays bytes as sent: decoding is only for the record.

Bounds: the final output is cut at the body limit (marked truncated, as before), an inner layer of a stacked encoding at 4 times the body limit (past that the body is not decoded), and zstd is read with one goroutine, low-memory mode and at most an 8 MiB window (the limit RFC 9659 sets for HTTP), so a declared larger window fails instead of allocating. Brotli's ring buffer is at most its 16 MiB format maximum. A 6 KiB zstd body of 200 MiB of zeros was kept as 256 KiB, the server at 24 MB resident. Decoding now needs the whole stream to decode: a body that errors part way is kept as captured instead of showing the part that came out. The flow detail's `request_body` and `response_body` gain `decoded` (the text is the decoded form) and `encoding` (the Content-Encoding as sent); `Message.Decoded` carries it and is not in the list JSON.

## 2026-11-22 · Proxy settings kept, and auto that follows trust

Interception and the passthrough list set through `POST /api/proxy` are written whole to `<data>/settings.json` through `userfile` (the user's alone): `{"version":1,"intercept":"auto|on|off","passthrough":[...]}`, and read at the next start. `FORMNET_INTERCEPT` or `FORMNET_PASSTHROUGH`, when set to a non-empty value, wins for that run and is never written: the file keeps what the person last chose in the client, and a POST changes only the fields it carries. A file that does not parse is reported at start and the defaults are used until the next change replaces it. Passthrough entries from the file are cleaned like the route cleans them (lower case, no spaces or slashes).

`POST /api/proxy` takes `intercept` as a boolean (true is on, false is off, as before) or as `"auto"`, `"on"` or `"off"`; anything else is a 400. The status body gains `intercept_mode` beside `intercept`, which stays the effective answer. In auto mode the proxy asks the root's trust state again every 10 seconds (`CA.TrustedNow`, which also refreshes the 30 second cache `/api/ca` reads) and opens or stops opening HTTPS for new connections without a restart, logging the change. This keeps the rule: HTTPS is opened only while the root is trusted or the mode is on.

Go reads the Linux system roots once per process, so its verifier would never see a change. On Linux the check reads the store from disk instead: the first readable bundle in Go's own list (or `SSL_CERT_FILE`) and the files in `/etc/ssl/certs` and `/etc/pki/tls/certs` (or `SSL_CERT_DIR`), compared by DER bytes, then the leaf is verified against the root for dates and usage. The files are read again only when a size or modification time changes, so a tick is a few `stat` calls. macOS and Windows keep the platform verifier, which asks the system store on every call.

## 2026-11-22 · An MCP server on stdio, and the agents generator

`formnet mcp` (`internal/mcp`) serves MCP on stdin and stdout, standard library only, as form.md's server does. Protocol 2026-07-28, the current revision on modelcontextprotocol.io/specification/versioning: a request whose `_meta` carries `io.modelcontextprotocol/protocolVersion` is served statelessly, must carry `clientCapabilities` (else -32602), gets `resultType` and `serverInfo` in its result, and an unknown version gets -32022 with the supported list. `server/discover` answers. A request without that key is a handshake-era request: `initialize` is answered for 2025-11-25, 2025-06-18 and 2025-03-26 (a dual-era server, as the versioning page allows and form.md does), and `ping` is answered there only, since 2026-07-28 removed it. Batches, null ids and malformed lines get JSON-RPC errors; `notifications/cancelled` stops the call and suppresses its answer. Stdout carries protocol messages only; one start line and warnings go to stderr.

Each tool call reads `<data>/endpoints.json` and `<data>/token` again, so a restart, a moved port or a new token is followed without restarting the client. The address must be a loopback IP, the HTTP client ignores proxy variables and follows no redirect, and the token goes only into the Authorization header: no answer, error or log line carries it. With no endpoints file, or nothing answering behind it, every tool returns an error result that says to start FormNET. The server starts no process and never opens the root's key.

Ten tools, each with its class in its annotations and its description. Read-only: `list_flows` (the API's filters, default limit 25, rows without headers or bodies), `get_flow` (bodies cut to 8 KiB by default and 64 KiB at most, flagged truncated), `list_hosts`, `machine_snapshot` (filtered and bounded), `proxy_status`, `ca_info`. Writes under `<data>/exports` only: `export_har`. Approval: `clear_flows`, `set_interception`, `set_passthrough`, marked destructive (they replace state rather than add to it) and idempotent. Credential headers read `[redacted]` in every answer, because whatever a tool returns enters a model's context. Arguments are checked against the same definitions the input schemas are built from: unknown names, types, enums, ranges and patterns are refused in the result so the model can correct itself.

The export folder is made with mode 0700 and refused when it is a link or a file; the HAR is written through `userfile.Create`, which fails on an existing name, so an export never replaces anything and a planted link at the name is not followed. The name is a plain file name (pattern, no separators, no `..`, no Windows device names). `userfile` has no folder helper, so on Windows the folder inherits the data folder's access list and only the file carries the user-only one.

`formnet agents sync` writes `agents/manifest.json` (tool names by class, protocol, skills), `agents/tools.json` (the full definitions as `tools/list` returns them), the skill pack's `references/mcp-tools.md`, and `.agents/skills` as a byte-identical copy of `.claude/skills`; `formnet agents check` fails when any of them is stale and when a skill breaks the format contract (name rule and folder match, description length and a use clause, no tags, em dash, emoji or README). Tool counts in documents come from that output.

## 2026-11-22 · System proxy, resend and recipes

`internal/sysproxy` points the system proxy at this run's real proxy address (the moved one when the preferred port was held) while the choice is on, off by default. The choice is `system_proxy` in `<data>/settings.json` (a version 1 file without it reads as false; the version stays 1); `FORMNET_SYSTEM_PROXY=1|0` wins for that run and is never written. `POST /api/sysproxy` keeps `true` only when setting it worked and keeps `false` always; on a system that is not supported it changes and keeps nothing. `enabled` in the status is the kept choice, `active` is read from the system (at most every 2 seconds) and is true when any setting points at this run's address.

macOS: `/usr/sbin/networksetup` on every enabled service from `-listallnetworkservices` (lines starting with `*` are disabled, the first line explains that). For each, `-getwebproxy`, `-getsecurewebproxy`, `-getproxybypassdomains` and `-getautoproxyurl` are read and saved; then `-setwebproxy`, `-setsecurewebproxy` (host, port) and `-setwebproxystate`, `-setsecurewebproxystate on`. SOCKS, the bypass list and automatic configuration are never written. A failure is read from the exit status and from an `** Error` line; one that names admin rights, privileges or authorization becomes a plain sentence saying an administrator account is needed, and every service already changed is put back first. A service whose proxy uses a password is refused before anything changes, because networksetup could not put the password back. Restoring writes the saved host and port and the saved on or off state, for each setting that still points at FormNET; a setting that had no server is only turned off, since networksetup cannot clear a server field. FormNET never runs sudo and never asks for a password.

Windows: `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` through advapi32 (`RegOpenKeyExW`, `RegQueryValueExW`, `RegSetValueExW`, `RegDeleteValueW`). `ProxyEnable`, `ProxyServer`, `ProxyOverride` are saved (absent stays absent on restore) and `AutoConfigURL` recorded; FormNET writes `ProxyServer=http=ADDR;https=ADDR`, keeps the person's `ProxyOverride` and adds `<local>` when it is missing, sets `ProxyEnable=1`, then calls `InternetSetOptionW` with 39 (settings changed) and 37 (refresh) from wininet.dll, loaded by its System32 path. The "Automatically detect settings" switch lives in the binary `Connections\DefaultConnectionSettings` value and is neither read nor changed. When `AutoConfigURL` is set (Windows) or an auto-proxy URL is on (macOS), `auto_config` is true and `reason` says the system prefers its automatic configuration. Other systems answer `supported: false` with the reason from the task.

Crash safety: `<data>/sysproxy.json` (`userfile`, atomic) holds the saved settings, the address set, this run's API address and pid, and is written before anything changes. A clean stop (SIGTERM, Ctrl-C, the desktop pipe closing, `POST /api/quit`, or either listener failing) puts back each setting that still points at FormNET's address and deletes the file, before the API shuts down. At start, before the certificate and the listeners, a file whose run no longer answers `/healthz` is handled: if the system still points at the recorded address the saved settings go back, otherwise the system is left alone; the file is deleted either way. A file whose run still answers is left to that run, so a FormNET being replaced restores its own settings; a new run turning the proxy on waits up to 5 seconds for such a file to go, refuses while its owner still answers, and inherits the saved settings of a dead owner whose address the system still points at. `formnet sysproxy restore` does the same without a server and refuses while the run that set it still answers.

Resend: `POST /api/flows/{id}/resend` goes through `Proxy.Resend`, which builds the request, checks the destination with the proxy's guard (a refusal is a 403 before any flow exists), and runs it through the same exchange code as a proxied request (`forward` now calls `exchange`, which panics only for a real client), with the proxy's transport and guarded dialer, normal certificate checks for https, a 10 minute bound and the proxy's lifetime. A hook marks the new flow (`resent_from`, `edited`, `client_process: "FormNET resend"`, `client_pid` FormNET's own) before the Store sees it and the id is answered once it is stored. `edited` is true when a field given differs from the capture. Headers lose hop-by-hop and `Proxy-*` names; `Content-Length` is recomputed from the body; a `Host` header becomes the request's host. A body captured decoded (`decoded: true` in the detail) is encoded again with the request's `Content-Encoding` (gzip, deflate as zlib, br, zstd) when that header is still the captured one; otherwise the body goes as given. Errors: not an http flow, or a truncated body sent unedited, 409; bad edits 400; a refused destination 403; the route body is read up to twice the body limit plus 64 KiB (413 past it) and an edited body may hold at most the body limit (413).

Recipes: `GET /api/recipes` answers `{proxy_addr, ca_path, platform, recipes:[{id, title, shell, lines, note}]}` for curl, Node.js, Python requests and pip, Java, Go programs and git, with sh and PowerShell on macOS and Linux and PowerShell only on Windows (no sh there by default; PowerShell's `curl` is another command, so the line calls `curl.exe`). Every value is single-quoted for its shell, Java `-D` arguments included, since PowerShell splits an unquoted `-Dname.part=value`. git uses `http.proxy`, the documented key that covers https URLs; there is no `https.proxy` key in git-config. Go's line sets `SSL_CERT_FILE` only on Linux and other Unix, because crypto/x509 reads it only there; on macOS and Windows the note says to trust the root. Notes say where a CA option replaces the default roots rather than adding to them.

## 2026-11-22 · The terminal dock's engine and the agent finder

FormNET carries the family's terminal dock (module 2.2.1, FormVis's `src/dock/`, copied unchanged by the web side) and its finder for agent programs. `internal/agentlookup` is form.md's Go port of FormVis's `agent_lookup.py` (Apache-2.0, version 1.0.1, the same MARK line): Claude Code (`claude`), Codex (`codex`), Cursor (`cursor-agent`, or `agent` only when its real path contains "cursor") and Antigravity (`agy`), looked for in the same order (the override variables `FORMNET_CLAUDE_BIN`, `FORMNET_CODEX_BIN`, `FORMNET_CURSOR_BIN`, `FORMNET_ANTIGRAVITY_BIN`; the engine's PATH; the known install folders per system; the login shell's PATH, or the registry Path values on Windows), then checked with `<path> --version` through the login shell, cached by path, time and size. That probe is the only way the finder runs a program, and only when the page asks for the status. `signedIn` is always null: FormNET runs no `auth status`. On Windows the engine's `Path` variable is passed as `PATH`, which the port reads by that name.

`internal/terminal` is the engine side, shaped on form.md's terminal: a PTY per tab (`creack/pty` on macOS and Linux, ConPTY on Windows through `golang.org/x/sys/windows`), opened only by `POST /api/terminal` from the page, at most 12 live tabs and 32 kept, 24 sockets. Agent tabs start the found program through the login shell (`$SHELL -l -c "exec ..."`, direct on Windows, `COMSPEC /c` for `.cmd` and `.bat`) and get no token: FormNET's MCP server is stdio and reads the data folder itself, so clause 11 has nothing to hand out and Antigravity's `mcp_config.json` step is skipped. The working folder is the home folder unless the page names a folder. Output keeps a 256 KiB scrollback for reattaching; a reader that cannot keep up loses output rather than holding the program.

Why the token and the origin check: a WebSocket is not covered by CORS, so any site the person visits can open one to 127.0.0.1, and a shell is the whole account. The upgrade therefore passes the server's guard (loopback Host, the run's token as `?token=` like the event stream, 401 without it) and then refuses any `Origin` other than `http://` plus the request's own Host, and any `Sec-Fetch-Site` other than same-origin (403); the WebSocket library checks the origin again. The page's CSP gains `ws://` of its own Host for that socket (older WebKit does not count ws: as 'self'); no other origin is added.

The child's environment is the person's own, less `FORMNET_TOKEN` and `FORMNET_DESKTOP`, plus `TERM`, `COLORTERM`, `FORMNET_TERMINAL=1` and `FORMNET_URL` (no token), and the family's PATH (the program's folder, the login shell's PATH, the known folders that exist, the engine's PATH). Nothing points it at FormNET unless the tab is opened with `capture: true`: then `HTTP_PROXY`, `HTTPS_PROXY`, `http_proxy`, `https_proxy` are this run's proxy, `NODE_USE_ENV_PROXY=1`, and `NODE_EXTRA_CA_CERTS`, `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE` are this run's `ca.pem`, replacing any the person had, so an agent started there shows in Flows. `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE` replace the roots those programs trust: while HTTPS is not opened (the root not trusted, or a passthrough host) OpenSSL and requests in that tab refuse real certificates; Node adds the root instead.

How children end: closing a tab (`DELETE`), a tab no page has been attached to for 60 seconds (the dock keeps its socket while the page lives and reattaches by listing after a reload), and the server stopping (SIGTERM, Ctrl-C, the desktop pipe closing, `POST /api/quit`) all end the tab's program. On macOS and Linux the shell is a session leader on its PTY: every process of that session (listed from `/proc` on Linux, from `kern.proc.all` on macOS, by session id) gets SIGHUP and SIGCONT, then after a second SIGKILL, so a job the shell put in its own process group goes too; a program that leaves the session with `setsid` is not followed. When the shell exits by itself what is left of its session is killed. On Windows each program runs in a job object with kill-on-close: the pseudo console is closed first (the console's close event), then the job is terminated; if the server dies without stopping, Windows closes the job handle and ends the tree. A crashed server on macOS and Linux leaves no job behind: the shell loses its terminal and gets SIGHUP from the kernel, but a program that ignores it stays.

Tests never start a real agent program: `agentlookup.Guard` runs before every start of a found program (the `--version` probe and an agent tab) and, inside a test binary only (`testing.Testing()`), refuses `claude`, `codex`, `cursor-agent`, `agent` and `agy` unless the file lives under the folder `FORMNET_AGENT_STAND_INS` names. A later test also sets a made-up `HOME`, a stand-in `SHELL` that runs `/bin/sh -c` without reading a profile, `PATH=/usr/bin:/bin:/usr/sbin:/sbin`, unsets the override variables, and sets `agentlookup.SystemFolders` to return nothing, as form.md's testguard does.

## 2026-11-22 · Rules, breakpoints, throttling and capture from other devices

One matcher (`internal/rules/match.go`) serves rules and the throttle's host list: `{scheme, host, port, path, method, query}`, compiled once to regular expressions. Host is a case-insensitive glob and `*.example.com` also matches `example.com`, as the passthrough list already does; path is a glob on the path alone where `*` crosses slashes; method may be a list (`GET,POST`); query is `name` or `name=glob` pairs joined by `&`, each of which must be present. Validation errors are `FieldError`s that name the field (`rules[2].match.port`), and the API returns them as they are.

`<data>/rules.json` (`userfile`, written whole, `{"version":1,"enabled":bool,"rules":[...]}`) holds the ordered list. A file that does not parse or validate is reported at start and no rule applies until the next change replaces it. A request is matched against the original request; rewrites accumulate in list order, the first map_remote wins, the first block or map_local ends the walk (rules after it do not run), and the first breakpoint of each stage pauses. Matching happens only where the proxy reads the HTTP: plain HTTP and HTTPS it opens. Tunnelled HTTPS and WebSocket upgrades pass unchanged; `GET /api/rules` says so in `https_note` and per rule in `notes`. Rules never apply to FormNET's own addresses (`ownTarget`), and a map_remote or edited URL still goes through the destination guard.

The rule path (`proxy/rules_hook.go`) is a separate exchange used only when a rule matches, so untouched traffic keeps the old path byte for byte. Body find and replace runs on text bodies (content type text, JSON, XML, JavaScript, form, SVG, or none) up to 8 MiB, on the decoded form. The changed body is sent without its `Content-Encoding` and with a new `Content-Length` rather than encoded again: identity is acceptable to every client, it cannot mismatch an encoder the client lacks, and it avoids carrying a second encoder for each coding; the flow carries a note saying so. A body over 8 MiB, or one that does not decode or is not UTF-8, passes unchanged with a note. A User-Agent a rule removes stays removed (net/http would add its own). Every flow a rule touched lists the rule names in `rules` and what happened in `notes`.

map_local: the path must be absolute, exist, and be neither the data folder nor inside it (refused at save). A file answers every match; a folder maps the part of the path after the match's literal prefix (the path pattern up to its first wildcard) under it. A `..` segment (decoded or not), a backslash, a symlink that resolves outside the folder or into the data folder are 403; a missing file is 404; `index.html` serves a folder. The file opened is compared with the one checked (`os.SameFile`). Content type comes from the extension.

Breakpoints (`proxy/breakpoints.go`): a paused exchange is in `GET /api/breakpoints` and on the stream (`breakpoint.paused`, then `breakpoint.resumed` with continued, edited, aborted, timeout or client_gone); the flow shows `paused` until it goes on. The request pauses after rewrites and map_remote, so the person sees what would go out. Continue takes an optional edit; an edited body that was shown decoded is sent without its Content-Encoding. Abort closes the client's connection. After the timeout (default 60 s, `POST /api/breakpoints`, kept in settings.json) the exchange goes on as it was, with a note; past the most paused at once (default 20) a match passes with a note, so a forgotten breakpoint never holds a program for ever. A client that leaves releases its pause.

Throttle (`internal/throttle`): one token bucket per direction shared by every throttled exchange and tunnel, as one slow link would be, burst 50 ms of traffic and at least 1500 bytes. Latency is added once per request the proxy reads and once per new tunnel. Requests are slowed at the client side (request body read, response body written); tunnels at the upstream connection. The API and the page never pass through the proxy and are never slowed; WebSocket frames are not throttled. Presets 3g, 4g, slow-wifi, custom; rates in kbit/s, 0 is no limit that way.

Capture from other devices (`proxy/remote.go`), the owner's rule: off by default. On, it listens for the proxy only on each unicast address of this computer (link-local skipped) at the proxy's port, read again every 10 s, beside the loopback listener. The API is never bound there. An allow list (CIDR or addresses, at least one entry to turn it on, a range holding every address refused) is checked on accept; a connection from outside it is closed before a byte is read and counted. Turning it off, or narrowing the list, closes the listeners and the connections of addresses no longer allowed. The proxy refuses to connect to its own remote listeners, and refuses a client on another device asking for this computer's loopback (by address or by a localhost name), so allowing a phone never opens local services to it. `http://formnet.cert/` is answered by the proxy itself and never resolved: a small page, `/ca.pem` and `/ca.cer` (DER) while the switch is on, 404 otherwise; the key is never read. `FORMNET_REMOTE_CAPTURE` and `FORMNET_REMOTE_ALLOW` win for a run and are not written; a change made in the page is kept in settings.json.

## 2026-11-22 · HTTP/2 to clients, WebSocket messages, an upstream proxy

HTTP/2 to clients (`proxy/h2.go`). Where HTTPS is opened, the leaf's TLS now offers `h2` and `http/1.1` by ALPN (the CA's own config still says `http/1.1`; the proxy sets the list on its copy). A client that picks h2 is served by the standard library's HTTP/2 server: no `golang.org/x/net` is needed, because net/http hands a connection to its bundled HTTP/2 server when the listener returns the `*tls.Conn` itself and ALPN chose h2. `serveH2` gives a one-connection listener exactly that connection, and the server's `ConnState` hook (closed) ends the listener, so the CONNECT handler waits for the whole connection as before. The HTTP/1.1 path is untouched. Every h2 stream reaches `serveOrigin` as its own request and so its own flow, through the same rules, breakpoints, throttle, body limit and destination guard. A CONNECT inside an opened h2 connection is answered 405. WebSockets over h2 (RFC 8441) are not offered: Go keeps extended CONNECT off unless `GODEBUG=http2xconnect=1`, so browsers open a separate HTTP/1.1 connection for a socket, which is relayed as below. Server push is not supported: FormNET never pushes, and Go's HTTP/2 client tells servers not to push, so there is nothing to relay. Upstream, the transport uses h2 to servers as Go does by default.

gRPC: `TE: trailers` is carried to the server (it is otherwise hop-by-hop), request trailers go with the upstream request, and response trailers are written after the body with `http.TrailerPrefix` (h2, and chunked HTTP/1.1). Bodies are still captured up to the limit while they pass and flushed on every read, so a stream reaches the client as the server sends it; measured: six chunks 500 ms apart arrived 500 ms apart through FormNET, then `grpc-status`.

Flows gain `client_proto` (what the program spoke to FormNET, set when a request is read; empty for tunnels) and `server_proto` (what the server answered with, only when a server answered: a rule's block or local file leaves it empty). The older `client_protocol` and `protocol` stay for existing readers. HAR `request.httpVersion` is `client_proto` and `response.httpVersion` is `server_proto`, each falling back to the old fields.

WebSocket messages (`proxy/wsframes.go`). The relay is the same `pipe`; each direction's connection is wrapped so that what it reads is also handed to a frame reader (RFC 6455: FIN, opcodes, masking, 16 and 64 bit lengths, fragmented messages, control frames between fragments). The reader works on a copy, never holds, changes or slows the bytes, and on framing it cannot follow (an unknown opcode, a fragmented control frame) it stops for that direction and the flow's `messages.parse_error` says so; the bytes go on unchanged. permessage-deflate (RFC 7692) is read from the server's 101: a message with RSV1 is marked compressed and inflated with `compress/flate` (the stripped `00 00 ff ff` and an empty final block appended); with context takeover the last 32 KiB inflated per direction is the next message's dictionary, and `*_no_context_takeover` turns that off per direction. A compressed message over 4 MiB, or one that inflates past 8 MiB or fails, is marked `not_decoded` (base64 holds the compressed bytes) and, with takeover, later messages of that direction are too, since the window is lost. Measured with a client that compressed with takeover: the second message (17 bytes for 33) was inflated correctly.

Bounds: per flow 1000 messages and 1 MiB of payload kept, at most 64 KiB per message (`truncated`); counts go on past that (`dropped`). Logs of at most 256 flows and 32 MiB of payload across all are kept; past that the oldest finished log is forgotten, and a log whose flow the Store no longer holds is forgotten when a new socket starts. The messages route then answers `evicted: true` with the counts from the flow. `GET /api/flows/{id}/messages?since=N&limit=M` lists messages with `seq` above N (seq counts every message, kept or not; `next` is the value to pass next). The stream's `flow.message` event `{flow_id, seq, dir, opcode, bytes, coalesced}` is sent at most every 100 ms per flow (the last message of the interval, and how many it stands for); the flow's `messages` summary `{count, bytes, dropped, deflate, close_code, close_reason, closed_by, parse_error}` is written to the Store at most once a second while open and once at the end. Measured: 2400 messages in about 2.8 s gave 28 events. The flow stays pending until the socket closes. Rules never change frames, and the throttle is as before (it does not slow WebSocket frames).

Upstream proxy (`proxy/upstream.go`). `{enabled, url, bypass, username, password}` in `<data>/settings.json` under `upstream`; `url` is `http://host:port`, `https://host:port` (TLS to the proxy) or `socks5://host:port`, with an explicit port and nothing after it; credentials written in the URL move into username and password. The transport's `Proxy` function sends plain HTTP as absolute-form requests to an http or https upstream and HTTPS by CONNECT; for socks5 the transport uses net/http's own SOCKS5 client. Tunnels and WebSocket dials go through `dialOut`, which sends CONNECT (with `Proxy-Authorization: Basic` when credentials are set) or a SOCKS5 CONNECT written here by hand (RFC 1928 and RFC 1929, about ninety lines), so `golang.org/x/net/proxy` is not needed and socks5 is in. SOCKS5 sends the name, so the upstream resolves it. A `ws://` socket through the upstream uses CONNECT as browsers do; an upstream that allows CONNECT only to 443 refuses it, and the flow says so.

The guard still decides the final destination: loopback addresses and localhost names never go upstream (they are dialled directly, as before), FormNET's own addresses and the remote listeners are refused, and a name that resolves here to loopback is refused. A name this computer cannot look up is left to the upstream (an intranet name only the corporate proxy resolves); without the upstream it fails as before. The upstream itself may be on loopback (a local proxy agent) but never FormNET's own address (refused at save and at dial). Bypass entries are host names and `*.suffix` patterns matched with the passthrough list's matcher (`flow.HostMatches`; a leading dot means `*.`), and IP addresses or CIDR ranges for literal addresses, at most 256. Every flow sent through it carries `upstream` (scheme://host:port, never the credentials). Errors name it: `the upstream proxy http://h:3128 is not reachable: ...`, `... answered "407 Proxy Authentication Required" to CONNECT host:443`, and a plain HTTP 407 through it gets `error` saying the upstream asked for credentials. The last failure is `error` and `error_at` in `GET /api/upstream` until a connection through it succeeds. A change closes the transport's idle connections; open tunnels finish on the route they had.

`GET /api/upstream` answers `{enabled, url, bypass, username, has_password, from_env, active, error, error_at}` and never the password; `POST /api/upstream` takes any of `enabled, url, bypass, username, password` (`password: ""` removes it; `has_password` is accepted and ignored so the page can send back what it read). `/api/status` carries the same object as `upstream`. `FORMNET_UPSTREAM_PROXY` (a URL, user and password allowed in it, or `off`) wins for the run and is never written; the bypass list comes from the file. A change made in the page while it is set applies on top of it for the run and on top of the file's setting in the file.

Why the password is in settings.json and not the system's password store: the same reasoning as the root key, which stays a file only the user can read. That file already holds a key that can open every HTTPS connection of the account, so a keychain entry for a proxy password would not make the data folder safer to expose; the store is different on each system (Keychain through `security` or cgo, the Credential Manager, Secret Service on Linux, which a headless or minimal Linux often lacks), would mean a child process or a dependency and, for the desktop sidecar, a prompt at start; and one file keeps backup and reset in one place. The file is written through `userfile` (mode 0600, the user-only access list on Windows). The cost is plain: a backup of the data folder carries the password, as it carries the key.

## 2026-11-22 · Sessions, HAR import, server-side filters, Copy all as cURL, the process of short requests

Session files (`internal/flow/session.go`). A `.formnet` file is gzip-compressed JSON: `{format: "formnet-session", version: 1, app_version, saved, flow_count, flows: [flow + request_body, response_body], messages: {flow_id: [message]}}`. A body is `{text}` when it is UTF-8 without control bytes, `{base64}` otherwise, with `decoded` when it is the decoded form of its Content-Encoding; messages have the messages route's shape. `flow_count` sits in the head so `GET /api/sessions` reads only the first bytes of each file. Writing streams one flow at a time (each flow re-read from the Store with its bodies, an evicted one written as listed). Reading dispatches on `version`: a newer version is refused with a sentence that says so, version 1 stays readable by later builds, an unknown key is skipped. Plain (uncompressed) JSON is read too, so a file someone unpacked to look at still opens. A session holds everything as captured, credentials included: it is the person's own file, and the save dialog says so; the HAR export stays redacted by default.

Saving writes `<data>/sessions/<name>.formnet` through `userfile.Create` (mode 0600 or the user-only access list; it fails on an existing name, so a save never replaces a file and a planted link is not followed) into a folder made 0700 and refused when it is a link or a file, as MCP's export folder is. The name is a plain name (no separators, `..`, leading dot, control characters or Windows device names, at most 100 characters).

Opening replaces the recording: one cleared event, then an added event per flow (a stream that falls behind gets resync and reloads). Every opened flow gets a new id (its messages and `resent_from` follow), `from_session: true`, `pending: false`, so it can never meet a live flow's id; a live exchange that was still open finds its flow gone and is dropped as after Clear. Live capture goes on into the same list while a session is open, because FormNET has one list and a person who opens yesterday's session usually wants to compare it with what happens now; the page can show either side with `from_session=1|0`. `/api/status` gains `session: {open, name, saved, flows, dropped, app_version, opened}`; Clear closes it. The page asks before opening; the API just does it.

Bounds. An uploaded session file may be 512 MiB: gzip shrinks text a lot but images and compressed bodies hardly at all, so a full recording at the default 256 MiB body budget comes near 350 MiB. It may decompress to 1 GiB, which stops a small file that inflates without end; flows past the Store's flow limit or byte budget are dropped oldest first while reading (`dropped`), so memory stays near the Store's budget rather than near that bound. Measured: three 30 MB text bodies saved as 181 KB.

HAR import (`internal/flow/harimport.go`) reads FormNET's, a browser's and Charles' HAR 1.2 entry by entry (512 MiB at most, uncompressed, bodies inline), trimmed to the Store's limits the same way, and appends: nothing is lost, so the page need not ask. Bodies come from `text`, or base64 when `encoding` is base64 (or FormNET's own `base64` comment), and are cut at the body limit; HTTP/2 pseudo-headers are left out; `timings.connect` and `wait` become `connect_ms` and `ttfb_ms`; Chrome's `_webSocketMessages` (send is client, receive is server, opcode 1, 2, 8, 9, 10, time in seconds) become messages of a websocket flow, as does `_resourceType: websocket` or a 101. `[redacted]` values stay as they are. A file that is not JSON, has no `log.entries`, or has an entry of the wrong shape is a 400 with that sentence.

Filters (`internal/flow/search.go`). `Store.Search` walks from the newest flow back and stops once `limit` flows matched, so a body search that reaches its bound has searched the newest flows. The body search reads at most 64 MiB of captured bodies per request, decoded text only (a body that is not UTF-8 is read but never matches), and the list answers `body_scanned_bytes` and `body_scan_cut`; past the bound older flows are left out, not guessed. Focus uses the rules matcher's host glob. The existing filters are unchanged and combine with the new ones by AND; the HAR, session and cURL exports take the same filters. Ignore (Charles's Ignore list) takes host globs with the same matcher and leaves their flows out after focus has narrowed the list. A leading `!` inverts one filter, as Chrome DevTools' `-` does, and the server does it rather than the page so the list, the exports and the counts agree: `status=!2xx` is every status outside 200-299 (no answer included), `method=!GET,HEAD` is neither, `type=!image/` keeps flows without a response, `process=!curl` keeps flows without a known process, `host=!` and `domain=!` leave out what the plain filter would keep, and `body=!secret` keeps flows whose bodies were read whole without finding it (a flow past the scan bound is left out, since nothing is known of it). The booleans invert with `0` as before; a bare `!` is a 400 naming the field.

cURL. Credential headers are redacted unless `secrets=1`, with the HAR export's list. Host, Content-Length and connection headers are left out; a body captured decoded drops its Content-Encoding header. sh feeds the body on stdin (`printf '%s' '...' | curl --data-binary @-`, or through `base64 --decode` for bytes that are not text), which keeps it byte-exact with no here-document newline. PowerShell writes the body to a temporary file from base64 (`[IO.File]::WriteAllBytes`) because piping to a native program in PowerShell 5.1 re-encodes it and adds a newline; it calls `curl.exe` on Windows (`curl` is Invoke-WebRequest there) and `curl` elsewhere, and wraps a value that holds a double quote in a small `Q` function that escapes it for PowerShell before 7.3, which drops embedded quotes when it calls a native program. cmd is a batch file: base64 echoed to a file and decoded with certutil; values are double-quoted with percent signs doubled, and a value holding a double quote gets the C runtime's quoting with every cmd metacharacter caret-escaped. Bodies over 64 KiB, and bodies FormNET captured only in part, are left out with a comment line.

The process of short requests (`internal/machine/attribute*.go`). The machine view's table is read every 2 seconds, so a request from curl or a script was over before it named anyone. On a miss the proxy now asks about that one port in the background, already when the connection is accepted, and is never made to wait: Linux asks the kernel's socket diagnostics over netlink for established TCP sockets (what `ss` uses; well under a millisecond, where /proc/net/tcp listed 1000 sockets in 2.4 ms here, long enough for curl to exit), falling back to /proc/net/tcp and tcp6, then looks for the socket's inode in `/proc/<pid>/fd` among that user's processes, newest first, for at most 300 ms, and reads `/proc/<pid>/comm`. macOS runs `lsof -b -w -nP -iTCP@127.0.0.1:<port> -sTCP:ESTABLISHED -Fpcn` (the end that is not FormNET's) and `ps -o comm= -p <pid>` for the executable's name, with a 2 second timeout. Answers are kept 5 seconds per port, misses 2 seconds; at most 4 lookups run at once. The answer names the stored flows of that client address that began in the last 30 seconds (an older connection on the same port is never named), and the Store keeps a client's pid when a later update of the same flow carries none. Windows keeps the netstat snapshot. Clients on other devices are never asked about. Measured on Linux: 12 of 12 curl requests of under a millisecond named `curl` with their pid; a program that exits within a fraction of a millisecond of its answer can still stay unnamed. Later, to close that race: while netlink looks for the socket, a second goroutine reads the open sockets, names and thread groups of the 8 pids just below `/proc/sys/kernel/ns_last_pid`, so a client that has exited by the time its socket's inode is known is still named; then the 64 pids below the last one are tried (wrapping at `pid_max`), then the whole of /proc newest first, with pids above the last one counted as older after a wrap; a lookup that still comes too late takes the machine view's latest snapshot, and the snapshot is otherwise asked only after the lookup's cache. Measured with 50 sequential curls through the proxy on a 2-core machine where another program used about 85% of a core: 45 to 50 of 50 named against a server that answers at once (requests of about 0.4 ms, the misses are lookups whose netlink answer came after curl had exited), 50 of 50 against one that adds 20 ms, and no data race with `-race` under the same load.
